# 运输车辆调度优化与仿真：中期报告初稿

小组：彭熙涵小组。组长：彭熙涵；组员：谢超瑜、向卓、秦观雲、邹沛龙。

整理日期：2026年10月9日。本稿根据当前代码、数据库记录及测试结果整理，可作为中期报告正文基础。用户已确认本次第3项只要求完成全员讲解材料准备；本稿与五人讲解稿均已准备完成。课程规定的阶段名称、成员个人贡献可按实际情况补充。

## 一、项目目标与当前进展

项目通过车辆、订单、路线和调度任务模拟运输过程，观察等待、空载、利用率、完成吨位和碳排放，并在固定实验条件下比较不同调度策略。

目前已经形成页面操作、后端执行、统计计算、数据库保存和结果比较的完整基础流程。实时监控复用现有高德地图和车辆展示；实验沙箱独立运行，不扣减实时场景的车辆或订单。

## 二、阶段一：监控与实验交互

实时监控页面提供五项指标卡、运行状态、车辆和订单列表、地图以及可切换指标的趋势图。点击详情可查看已有业务字段；没有接入的数据明确标注。地图沿用现有 SDK、POI 和车辆动画，不另建地图框架。

沙箱区分 Experiment（方案）与 Run（一次运行）。页面支持方案新建、保存、复制、种子设置、算法选择、事件开关、运行、进度、历史、重跑及结果比较。相同方案可产生多个 Run，修改方案不会覆盖旧 Run。已完成记录支持 JSON 导出，成对结果支持 CSV 导出。

## 三、阶段二：真实调度、统计和存储

前端调用项目真实后端接口。实时场景和沙箱共用调度计算：Baseline 按订单顺序处理，Optimized 使用有界候选筛选与启发式组合。两者使用相同计价规则，优化结果如实返回，不用基准结果替换退化结果。

订单按到达时间参与调度；任务分配后进入运输状态，仿真时钟达到结束时间才计入完成。沙箱冻结环境快照、配置、随机种子和模型指纹，在24小时窗口内运行，以已完成任务计算五项结果。

数据库连接使用连接池和超时控制。业务写入采用事务以及进程内、数据库层的互斥控制；扣货检查状态和剩余重量；重复提交通过幂等请求标识避免生成重复 Run。实验执行线程、等待队列、候选集合、任务数量和路线缓存都有上限，统计使用 SQL 聚合，避免读取全部长路线对象。

业务记录保存于 vehicle、transport_order、dispatch_task；实验保存于 sandbox_environment、sandbox_experiment、sandbox_run。实时统计保存于 live_stats_sample。后台默认每3秒计算采样，相同状态不重复写入；界面读取当前场景历史，服务重启恢复最后场景与仿真时钟，暂停状态不会自动启动调度。

## 四、统计图表如何帮助分析

| 图表 | 分析问题 | 解释方法 |
| --- | --- | --- |
| 指标卡 | 当前累计数值是多少？ | 同时读单位、完成规模和统计范围。 |
| 时间趋势 | 何时变化，变化速度怎样？ | 横轴使用时间间隔；只有一个采样点不能判断趋势。累计值上升不直接等于效率退化。 |
| 两次运行的柱形图 | 同一指标相差多少？ | 每个指标独立刻度，不能跨指标比较条长。 |
| 对比表 | 精确差值和改善率是多少？ | 先核对环境、种子、模型及控制参数；基准为0时不计算改善百分比。 |

总体等待时间为已完成任务的车辆等待分钟；空载里程以公里表示；车辆利用率为载重里程占总里程的比例；达成吨位只计已完成运输；碳排放由里程、油耗和2.68 kg CO₂/L系数估算。实时里程包含已分配任务，沙箱结果限于24小时内已完成任务，两种统计范围不能直接混作算法对比。

## 五、同条件实验结果

本节数据从后端已保存的 Run 读取；完整输入和结果见《中期报告同条件实验数据.json》。两次运行使用同一环境、模型指纹和控制参数，仅算法不同：2,419个POI、10辆车、24小时、每60分钟生成订单、随机种子123，五种随机事件均开启。

Baseline：RUN-f8d4559c-c3b2-4e88-b821-f990a0bfcd4c。

Optimized：RUN-41668d60-68dd-40c1-a28b-44fdde5ce802。

| 核心指标 | 单位 | Baseline | Optimized | 相对改善 |
| --- | --- | ---: | ---: | ---: |
| 总体等待时间 | min | 360.00 | 360.00 | 0% |
| 空载里程 | km | 3,417.89 | 3,417.89 | 0% |
| 车辆利用率 | % | 36.80 | 36.80 | 0% |
| 运输达成吨位 | t | 11.20 | 11.20 | 0% |
| 总碳排放 | kg CO₂ | 3,392.34 | 3,392.34 | 0% |

该场景中，两种策略的五项观测指标持平。这个结果支持“该场景未观察到改善”，不能推断算法在所有场景等价，也不能声称优化效果已经得到普遍验证。需要增加场景、种子和需求密度，再报告均值、波动及退化情况。不同种子或缺少模型标识的历史 Run 不纳入此项算法结论。

## 六、验证与证据

当前自动验证为23项Java测试通过，其中7项使用独立MySQL临时库；9项前端契约测试通过。验证覆盖事务回滚、并发扣货、幂等提交、时间完成边界、种子复现、队列满载、路线缓存、非法参数，以及图表单位、零分母、缺失值和真实时间间隔。

浏览器已实际验证 JSON 和 CSV 导出，检查未见脚本异常。重启前后实时 sceneId 和 simulationTime 一致，原有采样仍可读取。详见《2026-10-09-中期准备验收.md》及重启前后统计 JSON。

这些检查证明当前基础功能及被测边界可用，不代表长期运行、所有环境或大规模压力验证均已完成。高德地图底图依赖外部网络和浏览器渲染条件。
